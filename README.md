# 知遇·一席：让你的观点在讨论中找到位置

## 这个项目怎么玩

在《知遇·一席》中，每一道问题都会变成一间“认知教室”。

同一问题下的不同观点被转化为教室里的学生：观点越相近，座位距离越近；具有相似论证路径的学生会围坐在同一桌，形成不同的学习小组。

用户进入教室后，可以：

1. 点击任意学生，查看他的核心观点、理由以及对应的演示来源。
2. 听五个小组的课代表进行一轮结构化讨论。
3. 从黑板上了解当前讨论中的全班共识、核心争议和尚未解决的问题。
4. 写下自己对问题的初步判断。
5. 查看自己的观点在当前讨论样本中可能坐在哪里。
6. 认识附近的“同桌”，比较彼此观点的共同点和差异。
7. 回答同桌提出的一次针对性追问，补全尚未考虑清楚的条件。
8. 将整个过程沉淀为课堂笔记和《我的一席》。
9. 最终选择整理回答提纲，回到知乎亲自表达，或者沿着尚未解决的问题进入下一间教室。

整个过程不是让 AI 直接给出答案，而是帮助用户经历一次“听见别人—形成判断—接受追问—修正观点—完成表达”的学习闭环。

## 核心理念

### 1. 每个问题都是一间教室

传统信息流按照时间、热度或推荐算法展示内容，但用户很难快速看清不同回答之间的关系。

《知遇·一席》把讨论重新组织为空间：一位学生代表一条观点来源，一张课桌代表一种论证路径，座位距离表达观点之间的相似程度。

用户看到的不再只是一列回答，而是一张可以探索的讨论结构。

### 2. AI 不替用户回答

这个项目不以生成一篇完整答案为目标。

AI 的职责是帮助用户整理观点、发现分歧、核验依据，并指出还有哪些条件值得继续思考。最终的判断、回应和公开表达仍然属于用户。

我们希望保留人的思考过程，而不是用一段看似完整的生成内容替代它。

### 3. 先理解别人，再表达自己

很多表达问题并不是“没有观点”，而是没有充分理解已有讨论，也没有意识到自己的判断建立在哪些条件之上。

因此，产品不会让用户一进入页面就开始写答案，而是先安排一轮课堂体验：

- 看见不同观点；
- 听完小组讨论；
- 理解共识与争议；
- 写下初始判断；
- 接受一次有效追问；
- 再决定自己真正想表达什么。

### 4. Candidate Seat 不是“知识空白”

系统亮起的 Candidate Seat，只表示：

- 这个观点与当前问题相关；
- 观点在用户提供的材料中有明确依据；
- 在当前演示样本中的覆盖相对较少。

它不代表“全知乎没有人说过”，也不代表观点一定新颖、正确或更有价值。

系统只帮助用户找到一个值得继续核验和表达的位置，而不是替用户宣布发现了全新的知识。

### 5. 观点分组不代表支持率或正确性

学生的位置和颜色只用于表达论证结构。

同一桌的学生拥有相近的思考路径，但人数更多不代表观点更正确，颜色也不表示立场的强弱、排名或社会共识。

这个教室的目标是展示差异，而不是选出赢家。

## 当前 Demo 包含的功能

目前 Demo 已实现一条完整的本地演示流程：

- 40 位像素学生与 5 个观点学习组；
- 五个可打开的观点组检查器（共同理由、边界、代表来源与证据）；
- 学生详情、观点、理由与来源查看；
- 五组课代表结构化圆桌；
- 黑板三项总结；
- 用户初始观点输入；
- 通过本地 BFF 分析 Candidate Seat，并按 `evidenceId` 展示三项可核验证据；
- 同桌匹配、共同点和差异点；
- 一次针对观点漏洞的追问；
- 用户回应输入；
- 四段渐进式课堂笔记；
- Before → After 认知变化；
- 《我的一席》观点沉淀；
- 用户像素角色入席，教室人数从 40 变成 41；
- 知乎回答提纲查看、复制与返回知乎链接；
- Classroom 102/103 校园入口；
- Reset、第二次体验、手机适配与 Reduced Motion。
- 390×844 Bottom Sheet、一次性学生入场与 Claim → Seat 语义动效。

## 当前演示边界

当前版本是用于验证产品体验的 Mock Demo。

- 教室内容为人工构造的演示数据，不是真实知乎回答。
- 课代表发言、同桌追问、Sample Candidate 结果和回答提纲均为预生成内容。
- 当前只有指定的示例观点能够走通完整 Candidate 流程。
- 任意观点可以提交，但会诚实返回 `no_candidate`；不会套用不匹配的预计算结果。
- 同桌回应同样使用精确示例保护；任意回应不会生成固定课堂笔记或《我的一席》。
- 页面不会调用第三方 AI，也不会持久化用户输入。
- Classroom 102 和 103 目前是校园入口预览，尚未加载完整教室。
- “复制提纲”只会复制演示草稿；“打开知乎”只负责跳转，不会自动发布。
- 当前没有账号系统、数据库、任意问题实时建室或自由聊天功能。

所有 Mock 内容都会在页面中明确标注，不会伪装成真实数据或实时 AI 结果。

当前后端接入边界已经固定为两条接口：`GET /api/v1/classrooms/:questionId` 与 `POST /api/v1/candidate-seat`。页面、接口、Fixture 与测试共用 Zod Domain Schema；后续接入真实数据时替换服务端 Provider Adapter，不需要让前端直接调用知乎、LLM 或 Embedding SDK。

## 如何运行

运行环境要求：

- Node.js 24 或更高版本；
- npm；
- 现代浏览器。

启动项目：

```powershell
git clone https://github.com/yangqirui2020/Zhiyu.git
cd Zhiyu
npm ci
npm run dev
```

浏览器打开：

```text
http://localhost:3000/classroom/q_learn_programming
```

## 我们希望验证什么

这个 Demo 当前最重要的目标不是证明 AI 能生成多少内容，而是验证三个问题：

1. 用户能否快速理解“一道问题就是一间教室”？
2. 用户能否通过空间和互动看懂不同观点之间的关系？
3. 用户是否愿意在听完讨论、接受追问之后，亲自完成自己的表达？

《知遇·一席》希望建立的不是另一个答案生成器，而是一种新的学习与表达路径：

> 先看见讨论的结构，再找到自己的位置；
>
> 先完成真正的思考，再留下属于自己的这一席。
