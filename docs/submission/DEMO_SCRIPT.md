# 两分钟演示脚本

团队：知乎有你一席 · 杨骐瑞 · 湖北师范大学

演示前：使用最新版线上地址，桌面浏览器推荐 1440×900。先关闭不相关标签页，不展示密钥。使用示例观点和参考回应可完成可复现演示，过程中主动说明「精确示例结果」；需要展示实时能力时另开一次自己的观点测试。

| 时间 | 操作 | 讲解 |
|---|---|---|
| 0:00–0:15 | 进入 101 教室 | 很多人在知乎读了很多回答，仍说不清各自的理由，也不知道自己能补充什么。我们把一道问题变成一间可以探索的教室。 |
| 0:15–0:35 | 点一位学生，核对来源，再听各组 | 这里有来自知乎官方接口的 12 条真实回答摘要。每个学生代表一条来源，桌组表示论证路径；颜色和人数不代表谁正确。 |
| 0:35–0:55 | 使用示例观点 → 找到我的一席 | 示例提出用两周试学实验选语言。系统核对它与问题是否相关、笔记是否支持、在当前 12 条摘要里是否覆盖较少。只有条件满足才亮起一席。 |
| 0:55–1:15 | 认识同桌 → 让他追问我 | 系统根据这段观点和实际来源生成一次追问：反馈慢，到底是语言不合适还是环境与任务设置的问题？它是系统追问，不冒充真实答主。 |
| 1:15–1:35 | 填入参考回应 → 写下回应 → 核对笔记 | 演示用明确的参考回应。笔记保留原观点和回应，AI 整理草稿可对照核查。用户可以补充条件，也可以保持原观点。 |
| 1:35–1:50 | 我的这一席 → 入席 | 学习过程形成观点、理由、条件与待澄清处。入席表示参与讨论，不表示系统认证掌握。 |
| 1:50–2:00 | 展开三条提纲和知乎链接 | 最后带着三条提纲回到知乎，由人亲自完成表达。AI 帮助理解和练习，创作仍属于用户。 |

## 评委追问准备

**哪些是真实时数据？** 课堂是官方摘要的真实历史 Snapshot，采集于 9 月 15 日凌晨；任意观点与回应在提交时由 DeepSeek Pro 实时处理。完整示例采用精确匹配的预计算结果，模式全程可见。

**为什么不用多个 Agent？** 当前问题有明确步骤，采用可验证工作流更容易守住证据与时限。像素学生是来源的可视化，模型没有代替真人参加讨论。自主工具循环是赛后独立任务。

**如何防止幻觉？** Zod 限定结构，模型只选证据 ID，服务端核对摘要和笔记区间、当前问题版本及签名追问；AI 总结依然可能不准，所以保留原文、摘要和链接供人判断。

**失败怎么办？** 输入不会丢失，可重试；明确示例可以独立完成主路径。任意输入失败不能套用固定结果。不要临场把实时异常称为演示成功。
